# 燃やす埋める・Project Selection

各対象を 2 状態のどちらかへ割り当て、単独コストや対象間の関係を含む目的関数を最小カットへ変換する方法。最大流の実装ではなく、辺の向き、定数項、表現可能性を確認するためのノート。

## 1. 最小カットとの対応

各対象 `i` に頂点を作り、最小カット後の所属を状態に対応させる。このノートでは規約を次に固定する。

```text
i が s 側（残余グラフで s から到達可能）: 状態 0 = 選ぶ・燃やす
i が t 側                              : 状態 1 = 選ばない・埋める
```

状態の意味は問題に合わせて入れ替えてよい。ただし途中で規約を変えると辺の向きが全て逆になるため、コードを書く前に明記する。

`s-t` カットが支払うのは、`s` 側から `t` 側へ向かう辺の容量だけ。`t -> s` 方向の辺は同じ分割でも切断費用に入らない。この非対称性を使って、特定の状態組だけに費用を課す。

最大流最小カット定理により、構築したグラフの最大流値が目的関数の最小値になる。定数項を分離した場合は、最後にその定数を加減する。

## 2. 単項コスト

対象 `i` の状態 0 の費用を $D_i(0)$、状態 1 の費用を $D_i(1)$ とする。

```text
i -> t  capacity D_i(0)
s -> i  capacity D_i(1)
```

理由：

| `i` の所属 | 切れる辺 | 支払う費用 |
|---|---|---:|
| `s` 側（状態 0） | `i -> t` | $D_i(0)$ |
| `t` 側（状態 1） | `s -> i` | $D_i(1)$ |

### 負の単項コスト

容量は負にできない。$D_i(0)$ または $D_i(1)$ が負なら、

$$
m_i=\min(D_i(0),D_i(1))
$$

を定数項 `base` へ加え、

$$
D'_i(0)=D_i(0)-m_i,\qquad
D'_i(1)=D_i(1)-m_i
$$

を容量に使う。両状態から同じ値を引いているため、どちらが最適かは変わらない。最終的な最小値は

$$
base+\text{mincut}
$$

となる。

## 3. 2 頂点間の片方向ペナルティ

辺

```text
i -> j  capacity w
```

は、`i` が `s` 側、`j` が `t` 側のときだけ切れる。したがって

```text
i が状態 0 かつ j が状態 1 なら費用 w
```

を表す。

| `i` | `j` | `i -> j` の費用 |
|---:|---:|---:|
| 0 (`s`) | 0 (`s`) | 0 |
| 0 (`s`) | 1 (`t`) | `w` |
| 1 (`t`) | 0 (`s`) | 0 |
| 1 (`t`) | 1 (`t`) | 0 |

辺の向きは「費用を課したい `s` 側の頂点から `t` 側の頂点へ」と決める。

### ハードな含意

「`i` を選ぶなら `j` も選ぶ」、すなわち状態 `(i,j)=(0,1)` を禁止したい場合：

```text
i -> j  capacity INF
```

禁止状態だけが `INF` を支払う。`INF` を他の全有限費用の合計より大きく取れば、実行可能な解がある限りこの辺は切られない。

逆向きの `j -> i` を張ると、「`j` を選ぶなら `i` も選ぶ」という別の条件になる。論理式の矢印とグラフの辺の向きが一致するのは、このノートの「選ぶ = `s` 側」という規約による。

### 同値・同じ状態を強制

```text
i -> j  capacity INF
j -> i  capacity INF
```

とすれば、異なる側へ分かれるどちらの場合も禁止できる。

## 4. 同じ・異なる状態への費用

### 異なると費用 `w`

```text
i -> j  capacity w
j -> i  capacity w
```

2 頂点が異なる側にあるとき、`s -> t` を向く方の辺だけが切れるため、合計費用は `w`。`2w` ではない。

これは

$$
w[x_i\ne x_j]
$$

という分離ペナルティで、グリッドの隣接マスを同じラベルに寄せる、状態変更の境界長を罰する、といったモデルに使う。

### 同じと利益 `w`

「同じなら利益 `w`」を最大化する場合、全組について一旦利益 `w` を得ると考え、異なる場合にその利益を失う。

```text
base_profit += w
i -> j  capacity w
j -> i  capacity w
```

最大利益は

$$
base\_profit-\text{mincut}
$$

となる。

### 同じと費用・異なると利益

「同じなら費用」は、一般のグラフでは単純な最小カットで直接表せない。これは最小化において、異なる状態を好む相互作用だからである。「異なるなら利益」も、利益を失う費用へ直すと「同じなら費用」になるので同様。

相互作用グラフが二部グラフなら、一方の部の状態 0/1 を反転することで「同じ」と「異なる」を交換できる。それ以外では、別の構造・アルゴリズムが必要。

## 5. 利益最大化としての Project Selection

対象 `i` を選んだときの利益を $p_i$ とし、選ぶ状態を `s` 側とする。

- $p_i>0$：`s -> i` に容量 $p_i$
- $p_i<0$：`i -> t` に容量 $-p_i$

例えば $p_i=-5$ なら、追加するのは

```text
i -> t  capacity 5
```

であり、`t -> i capacity -5` ではない。容量は常に非負で、符号を変えたからといって辺の向きを反転させない。

`i` を選ぶと `i` は `s` 側、`t` は `t` 側なので `i -> t` が切れて損失 `5` を払う。選ばなければ `i` も `t` 側になり、この辺は切れない。一方、`t -> i` は選択時に `t` 側から `s` 側を向くため、カット費用に入らず損失を表せない。

正利益の合計を

$$
P=\sum_{p_i>0}p_i
$$

とすると、最大利益は

$$
P-\text{mincut}
$$

となる。

解釈：

- 正利益の対象を選ばないと `s -> i` が切れ、得られなかった利益を支払う。
- 負利益の対象を選ぶと `i -> t` が切れ、その損失を支払う。

依存関係「`i` を選ぶなら `j` も選ぶ」は `i -> j (INF)`。これは最大重み閉包問題の標準形。

### 最適集合の復元

最大流後の残余グラフで `s` から到達可能な頂点が選択集合。ACL なら

```cpp
auto selected = g.min_cut(s);
```

で取得できる。複数の最小カットがある場合、返る最適集合はそのうち 1 つ。

## 6. 補助頂点を使う条件

### どれか 1 つでも選ぶと費用 `C`

補助頂点 `g` を作る。

```text
i -> g  capacity INF  （対象となる全 i）
g -> t  capacity C
```

どれか `i` が `s` 側なら、含意により `g` も `s` 側となり `g -> t` の費用 `C` を払う。全て選ばない場合は `g` を `t` 側に置けるので費用はない。

固定費、施設を 1 回でも使用したときの起動費などを表す。

### 全て選ぶと利益 `R`

補助頂点 `g` を作る。

```text
base_profit += R
s -> g  capacity R
g -> i  capacity INF  （対象となる全 i）
```

全ての `i` が `s` 側なら `g` も `s` 側に置け、利益 `R` を失わない。1 つでも `i` が `t` 側なら、`g` を `s` 側にすると `INF` が切れるため `g` は `t` 側となり、`s -> g` の `R` を支払う。

「全て選ぶと費用」や「どれか選ぶと利益」は、この構造の辺を単純に逆にしても表せない。条件の AND / OR と、費用を課すのか利益を失うのかを真理値ごとに確認する。

## 7. 一般の 2 変数コストと劣モジュラ性

2 頂点 `i,j` の状態ごとの費用を

| | $x_j=0$ | $x_j=1$ |
|---|---:|---:|
| $x_i=0$ | $E_{00}$ | $E_{01}$ |
| $x_i=1$ | $E_{10}$ | $E_{11}$ |

とする。この項が `s-t` カットで表現できる条件は

$$
E_{00}+E_{11}\le E_{01}+E_{10}
$$

である。これは劣モジュラ条件と呼ばれ、「同じ側に置く費用の合計が、異なる側に置く費用の合計以下」という条件。

### 構成方法

定数項を $E_{00}$ とし、次を追加する。

```text
x_i=1 の単項費用: E10 - E00
x_j=1 の単項費用: E11 - E10
i -> j の容量   : E01 + E10 - E00 - E11
```

最後の容量は劣モジュラ条件により非負。単項費用が負になった場合は、「負の単項コスト」の方法で定数を分離して非負容量へ直す。

各状態で確認すると、

| 状態 | 定数・単項・有向辺の合計 |
|---|---:|
| `00` | $E_{00}$ |
| `01` | $E_{00}+(E_{11}-E_{10})+(E_{01}+E_{10}-E_{00}-E_{11})=E_{01}$ |
| `10` | $E_{00}+(E_{10}-E_{00})=E_{10}$ |
| `11` | $E_{00}+(E_{10}-E_{00})+(E_{11}-E_{10})=E_{11}$ |

となる。

劣モジュラ条件を満たさない項は、このままではグラフカットにできない。容量を負にして無理に表現しようとしてはいけない。

## 8. 燃やす埋める型の構築手順

1. 2 状態を `s` 側・`t` 側のどちらへ対応させるか固定する。
2. 目的関数を「支払う費用の最小化」へそろえる。利益は定数から失う利益を引く形にする。
3. 単項費用を `s -> i`, `i -> t` へ変換する。
4. 状態組ごとの追加費用を真理値表にし、どの向きの辺が切れるか確認する。
5. ハード制約は `INF` 辺、グループ条件は必要なら補助頂点で表す。
6. 全容量が非負であること、`INF` が有限費用の合計より大きいことを確認する。
7. 最大流を求め、目的値へ定数項を戻す。
8. 必要なら残余グラフの `s` 到達集合から各状態を復元する。

真理値表を書けば、辺の向きと係数の誤りをかなり防げる。特に有向辺は 4 状態のうち 1 状態だけに費用を課すため、頭の中だけで向きを決めない。

## 9. 典型例

各対象 `i` を燃やす費用が $A_i$、埋める費用が $B_i$、隣接する `i,j` の処理方法が異なると追加費用 $C_{ij}$ とする。

規約を「燃やす = `s` 側、埋める = `t` 側」とすると、

```text
i -> t  capacity A_i
s -> i  capacity B_i

i -> j  capacity C_ij
j -> i  capacity C_ij
```

を張る。

- 両方燃やす：`i -> t`, `j -> t` の単項費用だけ。
- 両方埋める：`s -> i`, `s -> j` の単項費用だけ。
- `i` を燃やし `j` を埋める：`i -> j` が追加で切れる。
- `i` を埋め `j` を燃やす：`j -> i` が追加で切れる。

したがってカット容量が元の目的関数と一致する。

## 10. 表現できない・注意が必要な条件

- 「2 つとも選ぶな」は、選択 `(0,0)` だけを禁止する項で、一般には単純な最小カットで表せない。
- 「ちょうど 1 つ選ぶ」も、異なる状態を強制するため一般には表せない。相互作用グラフが二部グラフなら片側反転を検討する。
- 選択個数をちょうど `K` に固定する大域制約は、通常の最小カットへそのまま追加できない。Lagrangian relaxation、最小費用流、DP などを検討する。
- `INF` 辺は論理制約を表すが、元の問題自体が実行不可能な場合には `INF` が切られる。最大流値が `INF` 以上なら実行可能性も確認する。
- 有向ペナルティと対称ペナルティを混同しない。異なると `w` は両方向に `w` であり、片方向だけでは一方の状態組にしか課金されない。
- 最大流値だけでなく、`base + flow` または `base_profit - flow` のどちらを返すか確認する。

## 11. 実装上の確認

ワークスペースでは `<atcoder/maxflow>`、提出用展開コードとして `mylib/acl/maxflow.cpp` を利用できる。

```cpp
atcoder::mf_graph<long long> g(N + 2);
int s = N;
int t = N + 1;

// g.add_edge(from, to, capacity);
long long cut = g.flow(s, t);
auto in_s_side = g.min_cut(s);
```

- 容量とその総和は `long long` にする。
- `INF` は有限容量総和 `+1` を基本に、オーバーフローしない範囲で決める。
- 同じ論理条件を重複して辺にし、費用を二重計上していないか確認する。
- 復元は元の頂点だけを見る。補助頂点の所属は通常、答えそのものではない。
