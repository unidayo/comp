# ABC348 F GPU experiment

Problem: https://atcoder.jp/contests/abc348/tasks/abc348_f

AtCoder's normal judge does not provide CUDA, so this is a local NVIDIA GPU
experiment rather than a submit-ready AtCoder solution.

## Files

- `abc348_f_gpu.cu`: CUDA direct pair-scan implementation, with optional
  `--bitset` mode.
- `abc348_f_cpu.cpp`: CPU bitset implementation for checking.
- `build.sh`: builds both binaries.
- `run_samples.sh`: checks the official samples against the GPU binary.
- `check_random.py`: compares CPU and GPU outputs on random cases.
- `gen_max.py`: generates benchmark inputs.

## Usage

```bash
cd gpu_experiments/abc348_f
./build.sh
./run_samples.sh
./check_random.py 100 200 200
./gen_max.py 2000 2000 0 > max.in
time ./abc348_f_cpu < max.in
time ./abc348_f_gpu --bench < max.in
time ./abc348_f_gpu --bitset --bench < max.in
```

In the Codex sandbox, GPU execution needs elevated GPU access. Running the
binaries directly from a normal terminal should not need anything special.

## Approach

The default GPU implementation directly scans all row pairs. For each pair
`(i, j)`, one CUDA thread scans all `M` columns, computes the parity of
`A[i][k] == A[j][k]`, and each block writes a partial count. This transfers only
the input matrix to the GPU and avoids the large mask table used by the bitset
method.

The alternative `--bitset` mode builds, for each column and value, a bitset of
rows having that value. For row `i`, it XORs the bitset for `A[i][col]` over all
columns. The resulting bitset contains exactly the rows whose number of equal
columns with row `i` is odd. This has less arithmetic work but transfers a large
`M * 1000 * ceil(N / 64)` mask table.

## Benchmark

Measured on a random maximum-size case generated by:

```bash
./gen_max.py 2000 2000 0 > /tmp/abc348_f_max.in
```

```text
N = M = 2000
CPU bitset:       real 0.26 user 0.22 sys 0.03 maxrss_kb 20036
GPU direct scan:  real 0.48 user 0.13 sys 0.03 maxrss_kb 116196
                  host_prepare_ms 0.000, h2d_ms 1.022, kernel_ms 19.201, d2h_ms 0.051
GPU bitset mode:  real 0.63 user 0.26 sys 0.13 maxrss_kb 616968
                  host_prepare_ms 181.875, h2d_ms 59.889, kernel_ms 4.457, d2h_ms 0.126
```

All three outputs matched. The direct-scan GPU kernel itself is about `19 ms`,
but the one-shot CUDA runtime cost makes the complete GPU process slower than
the CPU bitset implementation for this constraint size.
