# AHC066 Notes

## 問題の要点

- `N x N` グリッド上で、`M` 個のボールを対応するカゴへ運ぶ。
- ロボットは `(0,0)` から右向き、手ぶらで開始する。
- 基本操作は `F`, `R`, `L`, `S`。
  - `F`: 現在向きに1マス進む。壁があれば動かない。
  - `R`/`L`: 右/左に90度回転。
  - `S`: 手持ちボールと現在マスのボールを交換する。拾う/置く操作もこれで表現される。
- 追加操作は `M`, `P`。
  - `M`: マクロ記録開始/終了。
  - `P`: 直近登録済みマクロを再生。
- 出力長 `A` は `T` 以下。
- マクロ展開後に実行される基本操作も最大 `T` で打ち切られる。

## スコア

- 全ボールが対応カゴに置けた場合、絶対スコアは出力長 `A`。
- 置けなかった場合は `T * (M - V)`。`V` は正しいカゴ上のボール数。
- まず全ボールを確実に入れることが必須。その後はマクロで `A` を短くする。

## `T` の生成

問題文の生成式は次の通り。

```text
T = round((2X + 4M)^r * (2N^2M)^(1-r))
r = rand_double(0, 1)
```

`X` は次の座標列を順番に訪れるための、壁を考慮した最短移動回数。

```text
(0,0) -> ball0 -> basket0 -> ball1 -> basket1 -> ... -> ball(M-1) -> basket(M-1)
```

`r=1` なら `T=2X+4M`、`r=0` なら `T=2N^2M`。線形補間ではなく対数スケールの補間なので、広い範囲にばらける。

`2X+4M` 近辺はそこそこ厳しいが、指定順に最短路で運ぶだけなら全完遂できる程度の設計に見える。`2N^2M` 近辺はかなり余裕がある。

## 全ボール完遂について

グリッドは全マス連結なので、任意のボールから対応カゴへ必ず移動できる。

単純に各 `k` について

```text
ball k へ行く
S で拾う
basket k へ行く
S で置く
```

を繰り返せば全ボールを入れられる。初期状態では全ボール位置と全カゴ位置は相異なるため、順番に処理すれば基本的に衝突しない。

## 近い有名問題

ボールとカゴをペアにした配送なので、近いのは次の問題。

- Pickup and Delivery Problem
- single-vehicle pickup and delivery with unit capacity
- paired pickup-delivery TSP
- パス版 ATSP

今回の順序最適化は、各ボール運搬を1つのタスクとして見れば TSP 系になる。

タスク `k` の固定費:

```text
dist(ball[k], basket[k])
```

タスク順に依存する費用:

```text
dist(start, ball[first])
dist(basket[prev], ball[next])
```

したがって、順序最適化の本体は `basket -> ball` の遷移コストを持つパス版 ATSP。

## 現在の実装

メイン実装:

```text
heuristic_contests/ahc066/a/main.cpp
```

方針:

1. 壁を考慮した全マス間距離を BFS で前計算する。
2. タスク順を TSP 的に決める。
3. 実際の移動は、向き込み状態 `(r,c,dir)` で BFS して `F/R/L` の最短操作列を作る。
4. 各ボール位置とカゴ位置で `S` を出す。
5. 完成した基本操作列から頻出部分文字列を1個マクロ化する。

### 順序最適化

候補順序:

- 元の `0..M-1`
- 現在地から近い `ball -> basket` を選ぶ貪欲順
- 各タスクを最良位置に挿入していく挿入法
- 上位5候補からランダムに選ぶランダム化貪欲を800回

各候補に局所探索をかける。

- `swap`
- 区間反転
- 1点移動

評価値は壁を考慮した移動距離ベース。実際の出力では回転コストもあるが、順序評価ではまず移動距離を重視している。

### マクロ化

完成した基本操作列 `ops` に対して、長さ `2..80` の部分文字列を候補にする。

同じ文字列が2回以上出るものについて、非重複出現数 `c` を数え、次の利益を最大化する1パターンを選ぶ。

```text
gain = L * c - (L + 2 + (c - 1))
```

ここで `L` はパターン長。

`M pattern M` で記録すると、その場で1回実行されるため、追加の `P` は `c-1` 回でよい。

現状の制限:

- マクロは1個だけ。
- 長さ81以上のパターンは見ていない。
- 複数マクロの切り替えはしていない。
- マクロ合成はしていない。

## 2026-05-31 方針リセット案の試行

配送順最適化だけでなく、`plain_ops` を左から読みながら単一マクロをオンラインに張り替える圧縮器を追加した。

追加した候補:

- `M phrase M`: 現在位置から始まる基本操作列をその場で実行しつつ新マクロ登録。
- `M P suffix M`: 既存マクロを実行してから短い suffix を足し、`old_macro + suffix` を新マクロとして登録。
- `P`: 現在マクロが次の `plain_ops` に一致するなら再生。

各配送順について、次を候補にして最短の出力を採用する。

- plain な基本操作列
- 新しいオンライン圧縮
- 既存の短い移動マクロ込み経路探索。ただし計算量の都合で最良順序1個だけ

結果:

```text
100 cases valid
sum=26836 avg=268.36
```

以前のメモ上の `sum=28426 avg=284` より改善。単独のオンライン圧縮は悪化しやすかったため、現状は勝つ場合だけ使う候補扱いにしている。
