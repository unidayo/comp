# 動的遅延セグメント木

`dynamic_lazysegtree.cpp` の `lazy_segtree_sparse` は、長さ `n` の配列に対する点代入・区間更新・区間集約を扱う。座標が大きく、通常の遅延セグメント木を確保できない場合に使う。区間はすべて半開区間 `[l, r)`。

## 関数と初期値の前提

テンプレート引数は `S, op, e, F, mapping, composition, id`。`op` は結合則を満たし、`e()` は単位元、`id()` は恒等写像とする。`composition(f, g)` は **先に `g`、後に `f`** を適用する合成を返す。代入やアフィン変換では合成順序を間違えないこと。

`mapping(f, x, len)` は、長さ `len` の区間の集約値 `x` に更新 `f` を適用した結果を返す。子区間への適用と `op` による結合が一致する必要がある。区間加算・区間和なら `x + f * len` となるため、`S` に区間長を持たせる必要はない。

- `lazy_segtree_sparse(n)`：各区間の初期集約値を `e()` とする。
- `lazy_segtree_sparse(v)`：`vector<S>` の各要素で初期化する。`S` に `==` が必要。
- `lazy_segtree_sparse(n, range_e_fn)`：未生成区間の集約値を `range_e_fn(len)` で求める。

`range_e_fn` は区間の位置によらず長さだけで初期集約値を返し、`range_e_fn(0) = e()`、`range_e_fn(a + b) = op(range_e_fn(a), range_e_fn(b))` を満たす必要がある。全要素を `v` とする区間和なら `[v](ll len) { return v * len; }` を渡す。

区間最小値などでは、`e()` が「空区間の単位元」であり、実際の初期要素が `0` の場合もある。この場合はデフォルトのコンストラクタを使わず、長さが正なら `0`、長さが `0` なら `e()` を返す初期値関数を渡す。

## 操作

| 操作 | 内容 |
| --- | --- |
| `set(i, x)` | 要素 `i` を `x` に代入 |
| `get(i) const` | 要素 `i` を取得 |
| `apply(l, r, f)` | `[l, r)` に `f` を適用 |
| `prod(l, r) const` | `[l, r)` の集約値を取得 |
| `node_count() const` | 構築済みノード数を取得 |

各操作は `O(log n)`（利用者側の関数が定数時間の場合）。空区間の `prod` は `e()` を返し、空区間の `apply` は何もしない。`n=0` も構築可能。負のサイズや範囲外の操作は例外になる。

## メモリの削減

旧実装では `get` / `prod` でも遅延伝播を行い、未生成の子ノードを確保していた。現実装は祖先の遅延タグを引数で持ち回り、取得結果に適用する。**参照操作ではノードを一切増やさない。** 親に残る未伝播の更新は子の更新より新しいため、祖先のタグを後から適用する順序で合成する。

子ノードはポインタではなく32ビットの番号で表し、左の子の番号の上位1ビットに遅延フラグを格納する。区間長は再帰の区間端点から算出し、ノードには保持しない。64ビット環境で `S` と `F` がともに `long long` の場合、1ノードは旧実装の48バイトから24バイトになる。実際のサイズは `sizeof(Tree::Node)` で確認でき、`S` / `F` のサイズとアライメントに依存する。

ノードは256個単位の固定長ブロックで確保する。ノード領域の確保量は概ね `ceil(node_count() / 256) * 256 * sizeof(Node)` にブロック管理領域を加えたもの。巨大な `vector<Node>` の容量倍増や再確保時の一時的なメモリ増加を避けられる。構築済みノード数の上限は `2^31 - 1` 個で、配列長 `n` は非負の `long long` の範囲。

更新でノードが増えることはある。部分更新の際は、親に未伝播のタグがあれば両方の子を生成して伝播する。更新回数 `Q` に対してノード数は最悪 `O(Q log n)` で、不要になった部分木の解放は行わない。この削減だけでメモリ制限を満たせない場合、事前に全操作の端点を取得できるなら座標圧縮を検討する。区間和では圧縮前の区間長を `mapping` に渡せる設計が必要になる。

既存のコンストラクタと操作の呼び方は同じ。内部の `root` と子の表現は番号に変わったため、内部ノードをポインタとして直接操作していたコードは変更が必要。

## 確認結果（2026-10-13）

独立したライブラリテストで、素朴な配列とのランダム比較を36万操作実施。アフィン変換（加算・代入を含む）、点代入、点取得、区間和、空区間、3種類の初期化、非2冪のサイズを確認した。`n=LLONG_MAX` の座標と、参照・空区間更新でノード数が増えないことも確認。AddressSanitizer / UndefinedBehaviorSanitizer を有効にして通過した（環境制約により LeakSanitizer は無効）。

`S=F=long long`、`n=2^40` で全区間に1を加算し、固定seedで2万回の点取得を行う比較（GCC 15.2、C++23、`-O2`）：

| 実装 | ノード数 | 1ノード | 最大RSS |
| --- | ---: | ---: | ---: |
| 旧版 | 1,031,779 | 48 bytes | 51,632 KiB |
| 省メモリ版 | 1 | 24 bytes | 3,628 KiB |

これは読み取り時のノード生成の違いを確認する人工的なケースであり、更新が多い実際の解答での削減率は操作列に依存する。

### 速度比較（2026-10-13）

同じ旧版・新版を GCC 15.2 / C++23 / `-O2` でコンパイルし、`S=F=long long` の区間加算・区間和で比較した。`n=2^40`、最初に全区間へ1を加算し、固定seedの10万操作を実施。各ケースを3回測定し、実行時間の揺れを確認した。入力操作列の生成・初期更新・木の破棄は計測対象外。旧版と新版の各ケースのチェックサムは一致した。

| 操作列 | 旧版の3回 (ms) | 新版の3回 (ms) | 中央値の比較 |
| --- | --- | --- | --- |
| 点取得のみ | 127.402 / 120.936 / 114.973 | 0.500007 / 0.501156 / 0.485157 | 約242倍速 |
| ランダム区間更新のみ | 357.946 / 329.605 / 337.053 | 350.096 / 358.946 / 361.106 | 約6.5%遅い |
| ランダム区間更新・区間和が交互 | 308.562 / 321.107 / 298.862 | 222.932 / 261.024 / 218.355 | 約28%時間短縮 |

点取得のみのケースは、全体を1ノードのまま保持できる新版に有利な条件。参照時のノード生成を避ける効果は大きいが、すでに細かく分割された木でも同じ倍率になるとは限らない。更新のみでは番号からノードを引く処理などの影響があり、この計測では少し遅くなった。速度差は操作列と `S` / `F` に依存する。
