# 動的セグメント木

`dynamic_segtree.cpp` の `dynamic_segtree<S, op, e>` は、長さ `n` の配列をすべて `e()` で初期化した状態から、点代入、区間集約、区間初期化、境界探索を行う。`op` は結合則を満たし、`e()` は単位元とする。交換則は不要。

## 操作

区間はすべて半開区間 `[l, r)`。サイズと座標は `size_t`。

| 操作 | 内容 |
| --- | --- |
| `dynamic_segtree(n)` | 長さ `n` で構築。最初はノードを確保しない |
| `set(p, x)` | 点 `p` の値を `x` に代入 |
| `get(p) const` | 点 `p` の値を取得 |
| `prod(l, r) const` | `[l, r)` の集約値 |
| `all_prod() const` | 全区間の集約値 |
| `reset(l, r)` | `[l, r)` の値を `e()` に戻す |
| `max_right(l, f) const` | `f(prod(l, r))` が真となる最大の `r` |
| `min_left(r, f) const` | `f(prod(l, r))` が真となる最小の `l` |
| `node_count() const` | 現在の生存ノード数 |
| `allocated_node_count() const` | これまでに使用したスロット数。空き領域を含む |
| `node_size()` | 1ノードのバイト数（静的関数） |

境界探索は `f(e()) == true` を満たし、区間を伸ばした際に判定が真から偽へ変わっても、偽から真へは戻らないことが必要。非負の区間和に対する `sum <= limit` が典型例。負の値を含む和では一般に使えない。関数ポインタをテンプレート引数で渡す `max_right<f>(l)` / `min_left<f>(r)` にも対応する。

点代入、取得、区間集約、境界探索は `O(log n)`、全区間集約は `O(1)`（`op` などが定数時間の場合）。`reset` は解放するノード数を `k` として `O(k + log n)`。`n=0` も構築可能で、空区間の集約は `e()`、初期化は何もしない。範囲は `assert` で検査する。

## メモリの構造

この実装は各ノードに1つの座標と、その値・部分木の集約値を保持する。点代入の際に1経路分のノードを作る方式とは異なり、新しい座標への代入で増えるノードは1個。既存の座標への代入ではノード数が増えない。取得や境界探索は旧版からノードを生成しない。

新版では子ポインタを32ビットの番号に変更した。0が未生成の子を表し、構築済みスロット数の上限は `2^32 - 1`。配列長・座標は引き続き `size_t` なので、64ビット環境では大きな座標を扱える。中点は `a + (b - a) / 2` で計算し、端点の加算によるオーバーフローを避ける。

64ビット環境で `S=long long` の場合、1ノードは旧版の40バイトから32バイトへ減る。実際のサイズは `node_size()` で確認する。`S` のサイズとアライメントに依存する。

ノード領域は256スロット単位の固定長ブロックで確保する。概ね `ceil(allocated_node_count() / 256) * 256 * node_size()` にブロック管理領域を加えた確保量となる。巨大な `vector<Node>` の容量倍増や再確保時の一時的なメモリ増加を避ける。

`reset` で区間全体が不要になった部分木は破棄し、空き領域として再利用する。旧版の再利用用 `vector<Node *>` を廃止し、空きスロット内に次の空きスロットの番号を保持する。`union` を使い、`S` のデストラクタを呼んでから空き領域のリンクを構築するため、`string` などの非自明な型でも利用できる。

部分的な `reset` では、子が探索対象の区間にまたがるノードが残り、保持する点の値だけが `e()` になる場合がある。生存ノード数が非単位元の要素数に常に一致するわけではない。確保したブロックはデストラクタまで保持するため、`reset` によってOSへのメモリ返却は行わない。

## 境界探索の修正

旧版は部分木が探索開始位置をまたぐ場合でも、その部分木全体の集約値で判定し、判定が真なら探索対象外の値も取り込んでいた。新版では、`max_right` は `l <= a`、`min_left` は `b <= r` の場合に限って部分木全体を採用する。開始位置をまたぐ部分木は子と保持する点を順に調べる。

## 確認結果（2026-10-13）

素朴な配列との16万操作のランダム比較で、点代入・点取得・区間集約・区間初期化・両方向の境界探索を確認。さらにブロックをまたぐ解放と再利用、`n=SIZE_MAX`、文字列結合による非可換モノイドの5千操作、非自明なオブジェクトの構築・破棄数を確認した。AddressSanitizer / UndefinedBehaviorSanitizer を有効にして通過（環境制約により LeakSanitizer は無効）。

GCC 15.2 / C++23 / `-O2`、`S=long long`、`n=2^40`、固定seedの操作列で旧版と比較した。20万点代入、10万点取得と10万区間集約、全区間初期化後の20万点再代入を3回測定し、実行時間の揺れを確認。操作列生成と木の構築・破棄は計測対象外。チェックサムは両実装とも `6647706140` で一致。
