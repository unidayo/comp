# 黄金分割探索（実数・整数）

`golden_section_search.cpp` を貼り付けて使う。C++20 以上が必要で、他の自作ライブラリへの依存はない。

```cpp
auto f = [](long double x) { return (x - 2) * (x - 2) + 3; };
auto [x, value] = golden_section_search(-10.0L, 10.0L, f);
// x ≈ 2, value ≈ 3

auto g = [](double x) { return -(x - 4) * (x - 4); };
auto [argmax, maximum] = golden_section_search<false>(0.0, 10.0, g, 100);
```

引数は `(left, right, f, iterations=200)`。閉区間を探索し、既定で最小化、`<false>` で最大化する。端点は同じ浮動小数点型（`double`、`long double` など）で渡し、有限かつ `left <= right` とする。返り値は `{評価した最良の位置, その関数値}`。両端点と最後の区間の中点も候補に含める。同値の位置の選び方は保証しない。区間が一点なら一回の評価で返す。反復回数が0なら両端点と中点だけを評価する。

## 適用条件

最小化では「狭義減少 → 最小値の区間 → 狭義増加」、最大化ではその逆となる単峰関数が対象。最適区間は一点でも平坦でもよく、最適位置が端点にある単調関数も扱える。凸関数の最小化、凹関数の最大化が典型的な用途。

最適値以外の平坦区間がある一般の弱単峰関数には保証がない。例えば、右端付近だけ値が下がり、それ以外が一定の関数では、二つの内点が同値になり右側の最適位置を捨てる可能性がある。山や谷が複数ある関数の大域最適解も保証しない。`f` は同じ位置に同じ値を返し、NaN を含まないこと。

## 関数値を再利用できる理由

`rho = (sqrt(5)-1)/2 ≈ 0.618034` とし、区間幅を `W` とすると、内点を `left + (1-rho)*W` と `left + rho*W` に置く。最小化で左の値が右より大きければ左側を捨て、それ以外なら右側を捨てる。

残る区間幅は `rho*W`。`rho*rho = 1-rho` により、残した内点が新しい区間の内点の一つと一致する。その位置と関数値を引き継ぐため、最初に内点二つを評価した後は、次の比較の準備に新たな評価が一回だけ必要になる。[三分探索](ternary_search.md) は通常一回の比較につき二回評価するので、関数評価が重い場合に黄金分割探索が有効。

初期幅 `W` を `eps` 以下にする反復回数の目安は `ceil(log(W/eps) / log(1/rho))`。反復回数を `k >= 1` とすると、端点・中点の評価も含めて関数評価は高々 `k+4` 回。関数評価時間を `T` とすると計算量は `O(k*T)`、追加空間は `O(1)`。

これは理想的な比較での区間幅の目安であり、関数値の誤差保証ではない。丸めによって内点の順序が保てなくなった時点で終了する。関数値の比較が丸めで同値になる場合にも精度は制限される。

## 整数版（フィボナッチ探索）

`golden_section_search_integer.cpp` を貼り付けて使う。

```cpp
auto f = [](long long x) { return (x - 7) * (x - 7); };
auto [x, value] = golden_section_search_integer(-100, 100, f);
// x == 7, value == 0

auto g = [](long long x) { return -(x - 4) * (x - 4); };
auto [argmax, maximum] = golden_section_search_integer<false>(0, 10, g);
```

引数は `(left, right, f)`。端点は `long long`、両端を含む。実数版と同じ単峰性の条件で使い、最適区間以外の平坦区間は対象外。最後は1候補だけ残し、保存した評価値から `{最も左の最適位置, その関数値}` を返す。反復回数や許容誤差は指定不要。同じ位置の再評価は行わない。

実数版の内点を単純に整数へ丸めると、内点を再利用する関係が崩れる。整数版ではフィボナッチ数 `F[k]` を用い、幅を `F[k]`、内点のオフセットを `F[k-2]` と `F[k-1]` にする。縮小後の幅は `F[k-1]` となり、`F[k-1]-F[k-2]=F[k-3]` によって、一方の内点と評価値を正確に再利用できる。フィボナッチ数の隣接比は黄金比に近づく。

要素数を `N` とし、`F[k] >= N+1` となる最小のフィボナッチ数を選ぶ。オフセット `1..N` が元の区間に対応するように、開区間 `(0, F[k])` を探索する。区間外はすべての実値より悪い番兵で、`std::optional` の空値で表す。数値型の無限大や、区間外への関数評価は不要。

左の値より右の値が良ければ左の内点まで捨てる。それ以外では右の内点以降を捨てる。同値の場合も左側に同じ最適値が残るため、最も左の最適位置を保持できる。幅が `F[3]=2` になると開区間内には整数が一つだけ残り、その値は既に評価済みなので追加評価なしで返す。

初期の内点評価後は、区間の縮小ごとに新たな評価が高々一回。関数評価時間を `T` とすると `O(log(right-left+1)*T)` 時間、追加空間は `O(1)`。区間とフィボナッチ数の演算は `__int128` なので、`LLONG_MIN` から `LLONG_MAX` も扱える。`f` 内の演算は呼び出し側でオーバーフローしない型を選ぶ。離散凸関数なら隣接差の符号の二分探索も選択肢となる。

### typical90_ba の満点条件

[053 - Discrete Dowsing](https://atcoder.jp/contests/typical90/tasks/typical90_ba) は `N <= 1500` の狭義単峰な数列の最大値を求めるインタラクティブ問題で、各ケースの問い合わせが15回以下なら満点。

`F[16]=987, F[17]=1597` なので、`N <= 1500` では `k <= 17`。内点の初期評価2回と、その後の新たな評価が高々 `k-4` 回で、合計は高々 `k-2 <= 15` 回となる（`N=1` は1回）。区間外の番兵には問い合わせず、最後の答えも保存済みの値を使う。

`golden_section_search_integer<false>(1, N, ask)` と呼び、`ask(i)` で `? i` を出力・flushして返答を読む。返り値の関数値を `! value` として出力・flushする。返答が `-1` または入力終了なら即終了する。提出用の単体ファイルは `contests/typical90/ba/typical90_ba.cpp`。
